# Project continuation instructions

These instructions apply throughout this repository. Work within the user's authorized task; they do not add an approval step to authorized work.

1. Read `START-HERE.md`, `docs/continuity/project.json`, `backlog.json`, `decisions.json` and the task's protocol/evidence before changing code. Inspect the current branch and relevant open PRs. HQ is canonical; do not mistake an older Alpha stack for deployed HQ.
2. Treat JSON in `docs/continuity/` as the maintained record. Generated Markdown is a readable view; update the JSON and run `npm run continuity:write`. Keep original evidence and earlier decisions. Append a superseding decision rather than rewrite the reason for an old one.
3. Select or add a stable backlog ID. Record scope, status, dependencies, acceptance, owner role, exact evidence and next action. Unassigned people remain unassigned. At an interruption, leave the partial state and blocker explicit.
4. Preserve founder constraints: 1,000 reviewed questions per category before CCE resumes; contributor rates are unselected; treasury settlement and collection ownership remain disabled. A documentation edit, count milestone or planning receipt cannot open those gates.
5. Keep prior issued answer keys compatible. Question content stays server-only. Preserve original founding bytes and hashes; drafts, recollections and secondary application kits are not original timestamp proof.
6. Distinguish proposed, planned, implemented, internally checked, merged, deployed, pilot-accepted and independently reviewed. Give each assertion its actual evidence. School, public-service, government and military directions are proposals until their own agreements and acceptance exist.
7. Do not publish credentials, recovery material, learner records, private repository metadata or private agreements in this public record. Record private evidence by role and disposition, not a secret or an inferred identity.
8. Keep American English and the learning-first path. Respect the existing protocol and security boundaries. No new tracking, monetary flow or institutional data collection is implied by the roadmap.
9. Run checks appropriate to the change, including `npm run continuity:check`. Update `docs/continuity/WORKLOG.md`, the affected backlog item, and current checkpoint when facts change. Record test limits honestly. Include the PR/commit and final release result in the review record.
10. Source snapshots and bundles cover committed Git objects. External releases, provider databases, secrets, domains and original chat/files require their own controlled preservation. Do not claim complete recovery based only on a Git clone.
