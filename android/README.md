# Geek Protocol Android test package

Generated using Google Bubblewrap core 1.27.0. Run `npm ci` then `npm run generate` from this folder. The reviewed website manifest and supplied logo are the inputs; generated Android files are ignored and reproducible. Build with `cd generated && ./gradlew assembleDebug` using JDK 17 and an Android SDK. The Android test APK workflow builds the same project and retains the APK artifact for 14 days.

This is a separately identified debug test app (`xyz.geekprotocol.app.test`), not the final Play Store package or release signing identity. No production keystore or Play credentials are generated, requested or committed. The wrapper uses the live website and therefore its live account/data behavior. Use practice and private matches for device QA; do not treat this as an isolated test backend.

Without a matching certificate fingerprint in the website's Digital Asset Links, Android falls back to a browser/Custom Tab with browser UI. Do not publish placeholder fingerprints. A stable test certificate and verified domain association are a later step; Play App Signing will require its own production association. The APK does not imply fullscreen TWA verification, offline support or Play acceptance.

Phone checklist: install/launch/icon, sign-in and passkeys, Android Back, external links/wallet handoff, rotation, small screens, chess/private lobbies/reconnect, network loss/retry, exit and reopen. Founder acceptance is pending. No store submission or paid account action has been performed.

## Stable test identity (owner configuration required)

The manually dispatched `Stable signed Android test` workflow runs on main only. It builds a non-debuggable unsigned release APK in a job with no signing secrets, using `npm ci --ignore-scripts` and pinned Gradle wrapper validation. A separate minimal signing job downloads only that run's unsigned artifact, checks the exact test package and non-debuggable manifest, and uses Android apksigner. No npm, Gradle or repository build scripts run in the signing job. Only the signed APK and public association JSON are published; private material is removed on success/failure. The ordinary PR workflow also compiles the unsigned release variant without any secrets. Native project generation replaces the temporary loopback asset-server manifest URL with the canonical HTTPS website manifest before compilation.

Before storing any key, the repository owner must create the `android-test-signing` GitHub environment, restrict deployment branches to **main only**, and require the founder as a reviewer (prevent self-review where supported). Confirm these protections are available and enforced for this repository's plan. If unavailable, leave stable signing disabled and use an owner-controlled offline signing process. An `environment:` name in workflow YAML does not itself establish branch/reviewer protection. Do not dispatch stable signing until owner configuration is complete. Protect main with reviewed PRs as well.

Store `ANDROID_TEST_KEYSTORE_BASE64` and `ANDROID_TEST_KEYSTORE_PASSWORD` **only as environment secrets** in that protected environment, never repository/organization-wide secrets. Remove any older repository-wide copies before use. The connected tools cannot provision or verify these administrative settings, so their setup remains open; this PR creates no secret, environment, key or association.

Use a dedicated test key, never a Play production/upload key. On the owner's computer run `keytool -genkeypair -storetype JKS -alias geek-test -keystore geek-test.jks -keyalg RSA -keysize 3072 -validity 3650`; keytool prompts privately for password and identity details. Use the same store/key password, securely back up the JKS and password, and base64-encode the JKS directly into the protected environment secret. Never post passwords, key files or base64 in issues, chat or this public repo.

After protections and secrets are verified, run the reviewed workflow on main and approve its environment gate. It signs package `xyz.geekprotocol.app.test` and derives a public `assetlinks.json` from the actual APK certificate. Review the fingerprint, then separately deploy the JSON at `https://www.geekprotocol.xyz/.well-known/assetlinks.json` with a direct successful JSON response and no redirect. This statement grants only `handle_all_urls`, never `get_login_creds`. No placeholder or live association is deployed by this PR. Remove the dedicated test fingerprint from the live association when testing ends.

Install the matching non-debuggable stable test APK. The installed runner-debug APK has a different certificate and must be uninstalled before the first stable installation. Later builds using the same key can update it (increment versionCode for releases). Production Play signing/association remains separate. No stable signing run, fullscreen verification or Play acceptance is claimed.
