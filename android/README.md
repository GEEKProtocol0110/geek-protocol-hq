# Geek Protocol Android test package

Generated using Google Bubblewrap core 1.27.0. Run `npm ci` then `npm run generate` from this folder. The reviewed website manifest and supplied logo are the inputs; generated Android files are ignored and reproducible. Build with `cd generated && ./gradlew assembleDebug` using JDK 17 and an Android SDK. The Android test APK workflow builds the same project and retains the APK artifact for 14 days.

This is a separately identified debug test app (`xyz.geekprotocol.app.test`), not the final Play Store package or release signing identity. No production keystore or Play credentials are generated, requested or committed. The wrapper uses the live website and therefore its live account/data behavior. Use practice and private matches for device QA; do not treat this as an isolated test backend.

Without a matching certificate fingerprint in the website's Digital Asset Links, Android falls back to a browser/Custom Tab with browser UI. Do not publish placeholder fingerprints. A stable test certificate and verified domain association are a later step; Play App Signing will require its own production association. The APK does not imply fullscreen TWA verification, offline support or Play acceptance.

Phone checklist: install/launch/icon, sign-in and passkeys, Android Back, external links/wallet handoff, rotation, small screens, chess/private lobbies/reconnect, network loss/retry, exit and reopen. Founder acceptance is pending. No store submission or paid account action has been performed.

## Stable test identity (next step)

The manually dispatched `Stable signed Android test` workflow runs on main only, never PR code. It requires repository secrets `ANDROID_TEST_KEYSTORE_BASE64` and `ANDROID_TEST_KEYSTORE_PASSWORD`. The JKS must contain alias `geek-test` with the same store/key password. Use a dedicated test key, not a Play production/upload key. Create/back up the key on the owner's computer using `keytool -genkeypair -alias geek-test -keystore geek-test.jks -keyalg RSA -keysize 3072 -validity 3650`; keytool prompts privately for password and identity details. Base64-encode the file locally and put it directly into GitHub Secrets; never post passwords, key files or base64 in issues, chat or the public repo.

After secure setup and merging this reviewed workflow, run it on main. It signs the test APK and derives a public `assetlinks.json` from the APK certificate. Only APK + public association are uploaded; private keystore is removed even on failure. Review the real fingerprint, deploy that JSON at `https://www.geekprotocol.xyz/.well-known/assetlinks.json` with a direct successful JSON response and no redirect, then install the matching signed test APK. This JSON grants that exact test package/certificate a website association; no placeholder statement is deployed by this PR. The currently installed runner-debug APK has a different certificate and must be uninstalled before this first stable test installation. Later builds using the same dedicated key can update it. Production Play signing/association remains separate.
