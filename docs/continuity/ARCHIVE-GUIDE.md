## When Michael supplies a phone file or original conversation

1. Keep the original filename and bytes. Calculate SHA-256 before editing, rendering, extracting or renaming any derivative.
2. Search the asset register and relevant repositories for that hash. An equal byte hash means the same file; a different hash can be another version, not necessarily new content. Record near-duplicates after inspecting them.
3. Record source, supplied date, any reliable original timestamp, author/rights and public/private disposition. A screenshot's displayed date or a copied file timestamp alone does not establish authorship or completeness.
4. Check whether the original contains private messages, account details, keys, learner/personnel information or third-party material. Store the original in the agreed controlled archive when it cannot be public. A public redacted copy is a derivative with its own hash and reason; do not replace the original.
5. Add an asset ID, immutable location, hash, source/version relations and verification status. Link interpretations or factual claims to the relevant original pages/messages.
6. Include both the archive and its index in independent preservation and recovery checks. Git does not retrieve uncommitted files from a phone or automatically preserve external Library items.

The release ledger preserves merged metadata, not all comments, reviews, attachments or release binaries. The public repository directory excludes private repository names and contents.
