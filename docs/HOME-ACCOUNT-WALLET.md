# Home account and receiving-wallet controls

UX-029, November 13, 2026. Released in PR #287 as e177a551e22c3ff948af6a569d954e6a87cd0327. Production dpl_GtxZPNWRU3q6d48qJyhVrHm6oeSg is READY with both canonical domains. Canonical home, profile, rewards and both account/receiving clients returned HTTP 200 with exact source bytes. Actual-device acceptance remains separate.

The founder reported that returning home shows Sign in after account authentication and requested a Switch wallet control without KasWare. The home header was hardcoded, and the shared account controller returned before reading the session when a page had no sign-out button.

Home now opts into that controller with an account link. The existing credentialed, no-store passkey status GET drives My HQ and the profile link, hides returning-player sign-in guidance and exposes profile/progress plus a receiving-wallet shortcut. The request never creates a guest or invokes a wallet. Unknown status offers Account; a confirmed guest/401 offers Sign in. Browser history restore rechecks; overlapping reads deduplicate; revision checks discard stale replies. Transient failures retain the last known display, without granting any backend authority.

My HQ and Rewards expose Switch wallet beside the existing save/remove controls. Preparing a replacement clears only the unfinished input and confirmation checkbox, focuses the input and leaves the server-supplied saved address visible as text. No API mutation or credential request occurs until Save address. Network, destination, current version and fresh account passkey proof remain enforced by the unchanged server. Busy, unsupported and guest states stay locked. Long public receiving addresses wrap within the card.

Geek authentication, wallet connection and a saved receiving address remain separate. A desktop player explicitly connects a supported KasWare provider and approves the sign-in message; merely unlocking an extension does not authenticate Geek. After connection, the provider reports its selected address and account-change events. A phone/tablet player can instead authenticate with the same Geek passkey (or supported device access), then paste a receiving address from any Kaspa wallet and confirm its save with the account passkey. A pasted address alone neither signs into Geek nor proves wallet ownership. Changing the destination preserves the current player and progress. Mainnet settlement remains disabled.
