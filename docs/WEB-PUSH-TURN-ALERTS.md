# Device turn alerts — GAME-005

The device must explicitly opt in from the multiplayer lounge. Permission and a Push API subscription allow a service worker to receive an encrypted message when the lounge is closed. Browser/OS policies, connectivity and force-stopped apps can delay or prevent delivery; no guaranteed wakeup or exact delivery time is promised. iPhone support requires an installed home-screen web app.

Public/private VAPID keys are separate production environment values. Only the public key is returned to an authenticated player. The private key and CRON_SECRET never enter the repository, browser or logs. Preview is disabled. Sender subject is the canonical HTTPS website. No email/SMS vendor or paid notification subscription is added. The connected project is already Pro; its native five-minute Cron invokes the existing API function rather than adding a new database/provider. Standard provider usage remains applicable.

Subscription changes require a session, canonical Origin and same-site request context. Only known HTTPS browser push hosts and valid P-256/auth keys are accepted. No redirects or arbitrary callback URLs. At most three devices per player and 10,000 stored device subscriptions per deployment are accepted atomically; device bindings expire after 90 days and cannot be stolen by another account. Subscription data stays in private Redis and is removed on opt-out or a 404/410 provider response. Sign-out unsubscribes the device where that page is open; the service worker independently checks the current authenticated account before displaying any game alert.

The authoritative move CAS atomically places one pending event per room into a Redis outbox. A later move supersedes it; finished rooms remove it. Delivery uses a short leased lock, encrypted generic code/ply data, no opponent name/board/fleet/account identity, and per-device success receipts to avoid repeating a successful device on a partial retry. Expired devices are removed. Failed deliveries retry every five minutes, bounded to ten rooms per invocation and 48 hours per event. Provider acceptance is not proof that a phone displayed it. A crash after provider acceptance but before receipt can repeat delivery; a stable notification tag replaces that room's existing alert without re-alerting.

The worker checks My Games for matching room/turn/ply and suppresses stale or switched-account alerts. Offline fallback says only to open Geek and check saved games, linking to the lounge. Notification clicks use the exact same-origin room route when current and fall back safely if the old window cannot be navigated. No cache, fetch interception or offline app shell is introduced.

Synthetic real-Redis tests cover encryption, SSRF restrictions, owner binding, concurrent device capacity, durable move enqueue, continued no-expiry storage, partial delivery/retry, expired-device removal and finished-room cleanup. Worker tests cover current turns, stale/account-switched payloads and click fallback. Physical Android/iPhone acceptance remains open.
