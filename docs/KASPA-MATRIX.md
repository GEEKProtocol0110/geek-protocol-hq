# Kaspa space, planet and code-rain background

UX-026, founder request (Nov 11, 2026) to go beyond the UX-024 edge accents with a full-page "static matrix-like code" effect, then a layered space scene and a faint cypherpunk Kaspa planet on every page. This supersedes UX-024's "no infinite matrix rain" boundary for page backgrounds only; UX-024 edge feedback is unchanged.

**Layers.** A fixed, input-transparent stack sits behind content (`z-index` -4 to -1, below the sticky header at z 90, menus and dialogs):

1. **Back — space and nebula.** CSS gradients: a dark field with slow-drifting neon clouds in Kaspa teal, cyan and magenta/violet, plus a soft glow. No extra animation loop.
2. **Planet.** A pre-rendered photoreal cypherpunk Kaspa planet (dark tech surface, teal DAG/circuit lights, atmosphere rim, thin ring), large and clearly visible: about 70–95% of the viewport height on a 1280×800 desktop (roughly 560–760px), with about 50–70% of the disc on-screen, at about 0.55–0.75 opacity. Placement is viewport-fixed but **varies by route**: each page gets a deterministic corner, offset, size and rotation (an explicit map for the main routes, a stable pathname hash for the rest) so a given page always looks the same while pages differ from each other. It stays partly off-canvas so it does not sit in the middle of the reading column. Desktop and mobile image-set (`<picture>` with AVIF and WebP). A soft CSS glow pulse (no positional drift); motion is off when the planet is still. On phones it scales to about 80–110% of the viewport width, a little dimmer. On individual game boards it sits behind the board at a slightly lower opacity, but remains clearly visible.
3. **Middle — starfield.** A cheap canvas of dim stars, a few brighter glints, and faint teal DAG-like constellation lines, drawn in the same capped loop as the rain.
4. **Front — code rain and glitch.** The existing canvas rain (Kaspa-style K, digits, hex, BlockDAG marks and KAS/GEEK words), static scanlines, sparse specks, and a 240ms thin-band RGB slice at most every 9 to 22 seconds. No full-screen flashes.

**Planet image (easy swap).** The runtime files are `public/assets/kaspa-planet.webp` and `.avif` (desktop, under 120 KB, ~800px) plus `public/assets/kaspa-planet-sm.webp` and `.avif` (mobile). Paths are listed once as `PLANET_SRC` in `public/assets/kaspa-matrix.js`. To replace the art: drop the new render at `/workspace/brand/kaspa-planet/kaspa-planet.png` (or a similarly named PNG/WebP in that folder), optimize into those four public filenames, and leave the JS paths unchanged. The current files were optimized from Image Bot's `planet-b-transparent.png` (true alpha, no `mix-blend-mode`).

**Where it runs.** Space, nebula, stars and rain follow the original rain routes. The planet loads on **every** page, including individual game boards, `/ops/`, `/ops-login/` and `/sign-in/`. Pages that do not load `site.js` pull in `public/assets/kaspa-planet.js`, which imports the shared module. Those routes never start the rain, nebula motion or star loop; the planet is a still frame there.

**Readability.** Dark full-bleed sections and cards become dim translucent panels so the scene shows through; light paper and gold bands stay solid. The rain layer runs at 20% opacity on desktop and 14% on phones, with a calmer center mask. The planet is about 0.55–0.75 opacity on desktop (a little lower on phones and on individual game boards). Dark translucent panels and a light text-shadow keep hero and body copy readable where they overlap the disc. The home welcome hero drops its solid fill so the planet can show through, with a left-side scrim behind the title. Right-edge placements flip the asset horizontally so Planet B’s lit limb faces into the page.

**Performance.** There is one `requestAnimationFrame` loop for rain and stars, capped at 24fps (20fps under 700px wide or with Save-Data). Device pixel ratio is capped at 1.5 on desktop and 1 on phones. Phones get fewer rain columns and stars. Resize is debounced to 200ms. The loop stops on `visibilitychange` when hidden and on `pagehide`. Nebula and planet motion are CSS and pause with the still class. The planet is a static image (`pointer-events: none`, `aria-hidden`), with no WebGL and no extra loop. There are no network requests, no player records and no game hooks.

**Toggle.** There is no footer on/off button. Visitors see the effect by default. A leftover `localStorage` key `geek-matrix-background` is cleared on load and is never read or written, so a previous off-state cannot hide the scene. The hidden Stray signal terminal still accepts `matrix`, `matrix on` and `matrix off` as a session-only easter egg (`sessionStorage` for this tab). Under `prefers-reduced-motion` the rain is off by default (opting in through the terminal shows one still frame), and the planet is a still frame. Forced colors and print hide the stack.

**Games and quizzes.** Individual game boards (`/games/<game>/`), owner pages and sign-in pages never load the rain or nebula motion. Quiz and lobby routes (`/play/`, `/practice/`, `/quest/`, `/duel/`, `/royale/`, `/memory/`, `/challenges/`) get a single rain still frame at 6% opacity with no loop, and a still planet. Anywhere else, an active `body.is-playing` or `/play/` quiz screen stops the loop and dims the rain, and it resumes after play ends. Timers, the Gauntlet and board input are untouched.

**Loading.** It is imported from `site.js`. `<script type="module" src="/assets/kaspa-matrix.js">` remains on the pages that do not load `site.js` and already had the rain. Game boards, `/ops-login/` and operator UI load `/assets/kaspa-planet.js` instead. It is a same-origin external module, stylesheet and images, so the existing CSP (`script-src 'self'`, `style-src 'self'`, `img-src 'self'`) is unchanged.

**Validation.** Eight synthetic client tests are in `tests/kaspa-matrix.test.js`, plus local 1280x800 headless Chromium screenshots of the homepage, an inner page and a game page. Physical-phone and low-power-device acceptance remains open.
